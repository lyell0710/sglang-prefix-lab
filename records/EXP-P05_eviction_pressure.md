## 1. 目的与假设(跑前锁定)

小 KV 池 + 冷流量应使热前缀命中率退化，`evicted_tokens_total` 同步上升； 大池对照同负载不退化。（预注册用词"退化曲线"——见 §6 修正：实测为阶跃。）

## 2. 环境与配置

`scripts/bench_evict.py`：4 个热前缀（1536/2048）预热后轮转访问 16 次，每次热请求后插 cold_ratio ∈ {0,1,2,4} 条全唯一冷请求（2048）；串行 c=1 隔离排队效应。三个池位：`--max-total-tokens 8192` / `16384` / 默认（约数十万 token）；3 seeds。

## 3. 步骤

preflight → 小池臂（4 ratio×3 seed）→ /metrics → 默认池臂（2 ratio×3 seed） → 16k 阈值证明臂（cr4×3 seed）→ 聚合。

evicted_tokens_total 随 cr 单调上升（小池 33.9→66.3 万）；默认池全程无逐出。

## 6. 分析与结论

- **假设的"曲线"被修正为"悬崖"**（实测）：命中率只有 1.0 与 ~1/16 两个稳态， 没有中间态，seed 间 std=0。
- **统一模型（实测归纳）**：同一热前缀两次访问之间注入的 token 量（重用距离） D = hot_count × total_len × (1+cold_ratio) = 8192×(1+cr)。**LRU 命中 ⇔ 池 ≥ D**： 8192 池在 cr=0（D=8192，恰好）保命中、cr≥1(D≥16384)崩；16384 池在 cr=4(D=40960)崩；默认池 ≫ D 全保。三池 × 四 ratio 无一例外。
- **机理**：轮转访问 + LRU 是经典最坏搭配（循环工作集病态）：池略小于工作集时， 每个热前缀总是在被再次访问**之前**恰好被逐出，命中率不是按比例衰减而是归零（残余 1/16 ≈ 预热后首个热请求）。与 CPU cache 的 LRU thrashing 同构—— radix cache 没有魔法，它是一个带引用计数的 LRU 缓存。
- 工程含义：容量规划要按**热前缀重用距离**而不是"热集大小"配池；重用距离由并发流量结构决定，冷流量占比是一阶变量。

## 7. 异常、偏差与开放问题

- 默认池 `evicted_tokens_total` 指标缺失（从未逐出则 counter 不曝光）——按 0 记。
- 16k 池 full_hits=2/16 vs 8k 池 1/16：边界处首个周期存活多一拍，量小未深究。
- 未测 lfu 对照（PLAN 里"方向性一格"）：轮转访问下 lfu 理论上保热更好，列 backlog；不影响 LRU 主结论。
- cr=0 小池恰在 D=池 的边界上仍全命中：在途 lock_ref 保护 + 树祖先节点被更频繁触达可能各贡献余量，未拆分（开放）。
